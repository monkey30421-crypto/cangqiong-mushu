# 《苍穹母树：初枝试炼》Demo

这是依据仓库内现有设计文档制作的第一版可玩 Godot 原型。


当前固定显示规则详见 [`游戏显示与分辨率_设计规范_v0.2.md`](../游戏显示与分辨率_设计规范_v0.2.md)。

## 已实现流程

1. 登录界面保留账号和密码输入框；当前 Demo 只要求账号，密码允许为空且暂不参与验证。唯一账号 ID 由系统自动生成并保存，不在界面显示。
2. 新账号在进入主城前必须创建角色名：界面提示“请告诉我你的名字”，名字最多 `18` 个 UTF-8 字节，禁止空格和 Emoji，且不同账号不能重名。待命名账号重新登录时会继续进入命名界面。已命名账号再次登录会直接读取原名。
3. 角色从第一层主城“初枝集”的玩家住所出生。
4. 在连续三屏宽的枝上村集中移动，到第三屏最右侧点击世界树传送阵或按 `E`，打开副本选择列表。
5. 在副本选择列表中选中第一层副本“年轮树海”，再点击“确定进入”后，系统生成包含固定 `2A` 起点、固定 `2F` 首领点和 B-E 随机节点的 9 区域路线。
6. 起点完成祭坛树对话后，从三路传送阵选择路线；B-E 区域按普通、精英或变异类型完成两波怪物战斗，再通过祭坛树和传送阵继续推进。
7. 到达 `2F`、击败首领并完成祭坛树对话后，经过“恭喜通关”和副本结算界面返回主城。

主城第三屏的地面传送阵已叠加黄色金光循环特效：运行时使用 `20` 帧、`512×512` 帧格和加法混合，循环时长保持约 `5.18` 秒。传送阵本体仍烘焙在主城屏 `2` 背景中，动画节点只负责发光和能量流动。

项目以固定 1800×750 视口启动为全屏，登录界面、HUD 和绘制逻辑继续直接使用 1800×750 像素坐标，不使用整体放大层。主城和副本世界均为连续的 `5400×1200` 三屏坐标，运行时保持 `1:1` 像素比例，由摄像机裁取其中的 `1800×750` 区域，不缩放、不做非等比拉伸。背景使用最近邻采样与物理像素对齐，避免滚动时被线性采样模糊。显示器比例与 12:5 不一致时保留黑边。

新主城场景按最新地图规范由三张原生 `1800×1200` 单屏无缩放拼接为 `5400×1200`，三屏世界位置保持当前设定不变。运行时不显示主城可行走区和出生区的编辑覆盖层，也不接受相关鼠标编辑；已保存的可行走多边形和出生矩形仍分别从 `user://city_walkable_area.json` 与 `user://city_spawn_area.json` 读取。登录进入主城时会在出生矩形内随机出生，清空副本返回主城时仍回到传送阵附近。角色站在地面时，镜头通常将 Spine 动画 `x0、y0` 对应的脚底重心点保持在屏幕 `y=550`；主城和副本的纵向镜头均限制在 `0～450` 像素内，到达场景上下边缘后停止跟随，角色继续在屏幕内移动。进入场景时同样应用该限制，跳跃高度不影响镜头。

第一层副本以三层资源渲染：所有房间共用 `tree-sea-shared-background.jpg` 背景；`2A` 固定使用 `start` 前景和中景，`2F` 固定使用 `boss` 前景和中景；B-E 沿用原有地图编号分配逻辑，并由两张普通前景与三张普通中景按编号组合。前景决定当前房间的世界宽度：起点为 `2400`、普通房为 `5400`、首领房为 `3600`，均以原生像素从左侧对齐并裁取源图 `y=400..1600`。前景随相机 100% 移动，中景 50%，背景 10%。可行走区按前景资源共享；祭坛和传送阵配置继续按路线编号生效。

副本内置区域编辑覆盖层：绿色多边形为当前地图的可行走区域，金色多边形为祭坛树触发区域，蓝色椭圆为三座传送阵的触发范围。左键拖动多边形顶点可调整位置，左键点击多边形边线会插入顶点，右键点击顶点会删除顶点；左键拖动蓝色椭圆的中心十字可调整对应传送阵触发位置，拖动右侧手柄调整横向半径，拖动下侧手柄调整纵向半径，从而调整椭圆程度与大小。每张地图独立保存修改，玩家与怪物的移动限制、祭坛树交互及传送阵进入判定都会立即读取新配置；配置存放于 `user://dungeon_area_editor.json`。

登录界面已接入 `assets/ui/login/login-screen.png` 的最终 1800×750 设计图，账号框、密码框和登录按钮使用与图中位置一致的透明交互层；图片中的视觉设计不由 Godot 控件重复绘制。密码框暂时为可选项，留空即可登录。

当前主角使用最新用户提供的 `Character.json`、`Character.atlas`、`Character.png`（Spine 4.3.26）。三份源文件原样保存在 `assets/character/art/player_animations/source_spine/`，包含 20 个动画。受击动画配置已从旧名 `hit_SingleWeapon` 更新为 `hit_SingleWeapon2`，死亡动画从 `die` 更新为 `die_SingleSword`。

主角、怪物动作及技能特效默认全部使用原生 Spine，只有用户明确单独要求某项资源时才采用其他动画形式。主角骨骼为 `assets/character/art/player_animations/Character-data.tres`，直接引用 `source_spine/Character.spine-json`、图集和贴图；不再导出逐帧图片。动作由本地网页 `/actions` 配置，保存到 `config/character_actions.json`。原生资源读取由 `modules/spine_resources.gd` 统一处理，特效注册在 `config/spine_effects.json`。

当前源文件提供 20 个主角动画。游戏和网页均直接读取 Spine 时间轴的时长和事件；`action` 触发上下层特效，特效的 `hit_start` / `hit_end` 决定持续命中窗口，每个窗口对同一目标只命中一次。`actionEnd` 恢复操作，但动作仍继续播放。怪物动作通过 `config/monster_actions.json` 选择 `.tres` 骨骼和动画名，显式选择的骨骼会同时用于事件判定与画面播放。

游戏场景不显示顶部或底部的整条暗色遮罩，也不显示旧的区域、任务、敌人数、操作提示和结算文字。左上角角色状态栏恢复使用上一版本的 `assets/ui/status/player-status-frame.png`，以原资源的 `80%` 显示并保持上一版本的位置。其余 HUD 视觉不再由 Godot 线框样式临时绘制，而是直接使用最终 1800×750 示意图中的木质面板、藤叶装饰、彩色技能图标与中文标签；透明交互按钮仅负责点击和触屏命中，不重复绘制外框。提取后的透明 PNG 保存在 `assets/ui/hud/`：右上角为树珀与第二种货币；左下角为移动摇杆、状态与背包；右下角为攻击按钮及依次环绕的技能1、技能2、技能3、技能4、跳跃和闪避按钮。右下角所有按钮关闭图标扩展，按钮尺寸严格等于对应 PNG 的原始像素尺寸，不进行横向或纵向拉伸。

状态按钮会打开角色属性面板：面板内显示主角待机动作、当前角色名、当前生命/灵蕴与所在区域，并完整展示当前已经确认的 16 项主角属性。背包按钮会打开背包面板，两者均可通过面板中的关闭键、点击遮罩或 `Esc` 关闭。左下摇杆的底座保持固定，中间圆盘为独立显示层，会跟随鼠标或触屏拖动并在松开后自动回中。攻击、跳跃和闪避按钮已连接现有玩法逻辑；在主城传送阵附近，攻击按钮兼作移动端副本选择入口。主城右上角新增“选项”按钮，弹出列表中只保留“退出游戏”；副本中同一位置仍显示菜单，支持失败结算后退出副本或退出游戏。四个技能按钮已经提供独立交互入口，具体技能效果等待后续技能系统定义后接入。

当前 Demo 已按属性文档实装以下基础数值与结算：新角色自动获得人族 1 级的默认属性，基础攻击速度为 `2.00次/秒`；普通攻击使用攻击力、防御力与暴击伤害公式结算，命中怪物时会在其头顶显示上浮淡出的伤害数字，暴击使用更大的金色数字；移动速度直接影响位移速度；攻击速度决定手动普通攻击的最短间隔；灵蕴自然恢复会持续回蓝；灵蕴吸收会在普通攻击命中时恢复灵蕴。怪物完成一秒渐变后会按警戒范围追击并攻击玩家，首领使用一屏警戒和无限追击。副本击杀经验不会即时到账，而是在成功通关结算时统一发放；死亡、主动退出或关闭游戏按照失败处理，不增加经验。当前未加入升级成长曲线和技能消耗逻辑。

## 操作

- `WASD` 或方向键：移动。
- 拖动左下摇杆：移动（支持鼠标与触屏）。
- 主城传送阵附近按 `E`、点击传送阵或点击攻击按钮：打开副本选择列表。
- 副本中靠近祭坛树或已开启的传送阵按 `E`，也可以点击右下方临时出现的交互按钮。
- `J`：在副本中随时手动使用固定攻击“枝光横扫”；攻击动作不要求玩家先接近怪物，只有攻击判定发生时才检查攻击范围内是否有怪物并造成伤害。
- `Space`：跳跃，最高上升约 `200` 像素；必须完全落地后才能再次跳跃。
- `K`：向当前面朝方向闪避，总时长按正常移动速度的 `150%` 移动 `200` 像素计算，位移采用轻微快入慢出（曲线幂次 1.5，前半程时间约走完 65% 的距离）；闪避过程中锁定左右方向并禁止跳跃，但仍可用 `W/S` 或上下方向键以正常移动速度的 `20%` 纵向移动。
- 点击右下攻击、跳跃或闪避按钮：执行对应动作；四个技能按钮当前为后续技能系统预留。
- 点击状态或背包按钮：打开对应信息面板。

怪物不参与移动碰撞，玩家在普通移动和攻击过程中都可以与怪物重叠或直接穿过，不会被怪物卡住。

## 运行

用 Godot 4.7.1 打开本目录的 `project.godot`，或执行：

```sh
/Applications/Godot.app/Contents/MacOS/Godot --path /Users/junjiehou/Documents/苍穹母树/godot_demo
```

登录账号仅用于本地 Demo 验证，账号数据保存在 `user://accounts.json`。首次使用新账号登录时，系统生成不重复的隐藏账号 ID 并记录为“待命名”；合法角色名保存后才进入主城。现有角色名会被跨账号检查重复，名字以 UTF-8 计算最多 18 字节。当前阶段不校验或保存密码，密码输入内容不会影响登录；正式联网版本再把密码认证与账号唯一性约束迁移到独立服务端。

项目只有一个运行时脚本 `main.gd`，全部 Demo 业务流程集中在其中，未引入第三方框架或插件。

`tools/extract_hud_assets.py` 用于从最终示意图重建 HUD 透明 PNG。脚本只把去背景结果作为透明轮廓，支持保留示意图像素或使用干净的提取像素，避免把示意图中的树海背景一起带入实际关卡。右下角攻击与动作按钮采用等比缩放并居中放入原透明画布，禁止分别拉伸宽度和高度。

角色离地高度使用运行时参数 `character_height_px`（像素），站地为 0，仅跳跃轨迹更新，上升时增大、下降时减小，落地归零。角色显示纵坐标扣除此高度；地面位置、行走与攻击前移不改变高度。

怪物攻击同样要求横向、纵向、高度三个范围同时满足，复用角色攻击的范围公式。现有 attack_range_x/y 保留，新增 attack_range_height（像素，默认 0）和 character_height_px（离地高度，默认 0）；高度使用主角高度减怪物高度，不取绝对值。地面位置已到攻击范围但高度不足时，不造成伤害。

跳跃最高点 140 像素，上升 0.3 秒、最高点停留 0.2 秒、下落 0.3 秒，总时长 0.8 秒。上升与下落轨迹保持原有曲线。

## 角色模型与受击体积配置

本地网页 `http://localhost:3000/characters` 配置 `config/characters.json`，保存后重启游戏生效。

- 主角 ID 固定为 `1`；怪物 ID 从 `101` 起，类型由角色配置中的 `monsterType`（`normal`、`elite`、`mutation`、`boss`）显式定义，不按固定 ID 推断。新增角色默认普通怪；副本波次按类型字段查找匹配角色配置。
- `modelResource`：主角与动画怪物选择原生 Spine `.tres` 骨骼，主角默认 `assets/character/art/player_animations/Character-data.tres`，需包含动作配置引用的全部动画；现有 PNG 静态模型按原图显示。
- `x`：受击左右总宽度，脚底中心左右各延伸 `x / 2`；`h`：脚底向上的身体高度。单位均为像素，独立于模型显示尺寸。
- 怪物 `hitPushbackDistancePx`：普通受击沿远离攻击者的方向平移，默认 40 像素，0 关闭；每次受击在 120 毫秒内完成，受可行走区域约束，顿帧期间暂停。`canBeLaunched`：达到现有倒地条件后是否可击飞，默认非首领为 true、首领为 false，可逐个覆盖；关闭时使用原地倒地，开启时沿用原有击飞轨迹。已在空中的怪物继续当前轨迹，受击不重置腾空过程。
- 怪物 Spine 与 PNG 均按资源原始大小显示，朝向只做左右镜像；不按受击 H 或怪物类型缩放，也不叠加上下浮动。血条、名称与伤害数字按模型原始边界定位，战斗击飞仍按实际离地高度显示。
- 受击检测为技能 X/H 范围与身体矩形相交；纵深 Y 不加体积，仍比较脚底纵深差。跳跃时身体矩形随离地高度移动，主角和怪物均生效。
- 持续判定窗口继续保持同一目标每个窗口仅命中一次。相交包含边界；角色完全高于或低于技能高度区间时不命中。

### 闪避攻击输入规则

闪避可立即打断正在播放的攻击动作（含命中停顿和 actionEnd 后的收尾），同时清除该角色的攻击特效、命中窗口和连段缓存。闪避过程中任意时刻点击攻击，立即取消剩余闪避，发动 `2005`；此时读取左右方向键 / A、D / 摇杆横向输入决定攻击朝向，没有横向输入则保持闪避朝向。闪避攻击按配置的前移距离和时长独立位移，不会补走剩余闪避距离；前移时长为 0 时，按完整动作时长分配。自主移动仍在 actionEnd 后恢复，闪避可在冷却就绪时再次打断攻击；受击、倒地、起身和闪避冷却限制保留。

跳跃攻击（2004）落地时立即打断，切回待机，并清除剩余攻击特效与命中窗口。落地当帧不接受自主位移，下一帧恢复正常移动。

跳跃攻击期间允许方向键、WASD 和摇杆自主移动，按正常移动速度与地图边界处理，移动不会切断攻击动画；落地仍立即结束跳跃攻击。

受击会取消攻击与其剩余命中窗口并播放受击动作。滚动 5 秒内实际扣血严格超过最大生命 30% 时击倒；击倒触发后清空本轮伤害累计。主角与普通、精英、变异怪被击倒时使用 `floated` 姿势，向受击源反方向击飞最多 200 像素，并以最高离地 80 像素的弧线在约 0.55 秒内落地；位移每帧限制在当前可行走区域内。BOSS 保留原倒地行为，不播放击飞动作且不发生击飞位移。倒地期间免伤且不可行动，倒地计时结束后主角无方向输入会播放 `die_Up` 起身动画；按住方向时仍播放专用翻滚起身动作。怪物倒地不可行动，起身优先播放自身 Spine 的起身动作；死亡仍优先结算。主角倒地/死亡分为“击飞中 → 击飞落地 → 躺地循环”和“原地死亡 → 跪地循环”；存活怪物击飞落地后进入躺地循环，原地倒地保持末帧等待起身，不配置跪地循环。死亡怪物在原地死亡或击飞落地动作播放完后移除模型、阴影和特效，击飞中死亡会先完成飞行。地面循环可独立绑定动画，未配置时保持前一阶段末帧；存活目标继续起身；主角死亡保留姿势，怪物死亡动作结束后消失。怪物动作配置包括待机、移动、攻击 1、攻击 2、技能 1、技能 2、受击、击飞、击飞落地、躺地循环、原地死亡和起身；技能动作仅 `monsterType` 为 `boss` 的怪物使用，详情见 `../map_editor/MONSTER_ACTIONS_README.md`。

怪物攻击与主角共用事件判定流程：实际播放动作的 `action` 事件触发上下层特效，伤害仅在特效成对 `hit_start` / `hit_end` 窗口内判定。起手时不直接扣血；窗口实时检查位置、高度、朝向和主角 X/H 体积，每个窗口对主角只命中一次，上下层相同窗口共用记录。受击、倒地和死亡取消剩余攻击判定；缺少 action 或有效特效窗口不造成伤害。详情见 `../map_editor/MONSTER_ACTIONS_README.md`。

## 通用受击特效

技能特效的原生骨骼源统一为 `assets/skill_effects/skilleffect_jd_dg1.spine-json`，`skilleffect_jd_dg1-data.tres` 直接引用该文件；原普通 `.json` 源已迁移，避免 Godot 将其作为不支持的资源类型而加载失败。网页选项与已保存配置仍沿用逻辑标识 `skilleffect_jd_dg1.json`。原生特效注册表保留这一标识及资源路径，主角与怪物共用有效的 Spine 资源，每次 action 创建独立的单次特效实例。

`assets/scene/effects/hit_common/` 保存用户提供的 `hitEff_common` Spine、atlas 和贴图，按原始骨骼尺寸播放，不额外缩放。`modules/hit_effects.gd` 管理一次性播放、目标跟随、摄像机偏移和结束清理。

主角与怪物实际扣血时均播放受击爆点；空挥、重复命中及无敌免伤不播放。接触位置取攻击特效显示范围与目标 X/H 受击框相交矩形的中心点，左右攻击使用相同规则；若配置伤害范围超过特效图形，则取目标迎击面上最接近特效高度的位置。播放期间保持相对受击部位的偏移，随目标 X/Y 和离地高度移动，约 0.367 秒后释放；切换地图时清除旧爆点。

## 场景深度与特效层级

`modules/scene_depth.gd` 每帧按个体脚底的地面 Y 值稳定排序，Y 越大越靠前；排序不使用跳跃高度、Spine 资源偏移、相机偏移或粗略的 Y 分段。主角、原生 Spine 怪物、图集/PNG 怪物、死亡动作和独立祭坛树采用同一顺序。怪物身体使用独立绘制节点，避免立即绘制的 PNG 固定处于某一全局层。

主角与怪物的上层特效统一位于所有个体之上，下层特效统一位于所有个体之下；阴影低于下层特效但高于场景底图，受击爆点和伤害数字在个体上方。HUD 保持独立 CanvasLayer，不参与世界 Y 排序。

## 主城打击范围测试

主城中心的可行走区域放置一只使用普通怪角色配置的测试怪物。最大生命固定为 20，命中扣血后立即回满，不会死亡，不产出掉落或经验。它不主动移动、不追击、不攻击；受击、击退、击飞和倒地仍按正常怪物配置与规则处理，不会自动传回出生位置。

主城可用 J 或右下攻击按钮进行普攻、连段、跳跃攻击和闪避攻击，沿用实际技能范围与 Spine 事件命中窗口。靠近传送阵时攻击按钮仍用于进入副本，J 可直接攻击。测试怪物每次进入主城重新放置，进入副本时清理。
